    PTO IR 概述¶

    • Version: v 0.1
    • Date: 2026-02-14
    • Author: Wenbo Sun

    1. Overview¶

    The PTO Dialect (pto) is an MLIR dialect for expressing tile-based computations targeting Ascend NPU hardware. It is part of the PTOAS (PTO Assembler & Optimizer) compiler toolchain.

    • Dialect name: pto
    • Source: include/PTO/IR/

    PTO IR Level Model¶

    PTO IR is organized as a hierarchical, multi-level IR stack and intentionally exposes multiple abstraction levels to external users and frameworks.

    ┌─────────────────────────────────────────────────────────────────┐
│                      PTO IR 层级模型                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Level-1 (SSA-centric IR)                                      │
│  ├─ pto.tile 是 SSA value                                      │
│  ├─ PTO-AS 负责内存分配和存储规划                                │
│  └─ 公共接口仍在设计中                                          │
│                                                                 │
│  Level-2 (DPS tile-buffer IR) ◀── 当前文档重点                  │
│  ├─ pto.tile_buf 使用目标传递风格 (DPS)                         │
│  ├─ 显式的 buffer 对象，非 SSA 语义                             │
│  └─ 用户/框架管理 buffer 生命周期                               │
│                                                                 │
│  Level-3 (Low-level scheduling IR)                             │
│  ├─ 流水线/事件同步显式化                                       │
│  ├─ 用户直接控制执行顺序                                        │
│  └─ 最大控制力，适合专家使用                                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘

    这些层级从 Level-1 逐步降低到 Level-3，服务于不同用户和集成的优化与控制需求。本文档专注于 Level-2 和 Level-3 接口。

    Hardware Memory Hierarchy¶

    GM (Global Memory)                    ─── DDR/HBM，几十 GB
│
├─ MAT (L1 Cache)                     ─── 512 KB
│  │
│  ├─ LEFT  (L0A - left matrix buffer)  ─── 64 KB
│  ├─ RIGHT (L0B - right matrix buffer) ─── 64 KB
│  ├─ ACC   (L0C - accumulator)         ─── 128-256 KB
│  └─ BIAS  (bias buffer)               ─── 较小
│
└─ VEC (UB - unified buffer)          ─── Vector 单元使用的 UB

    数据流向:

    GM ──TLOAD──▶ MAT ──TMOV──▶ LEFT/RIGHT ──TMATMUL──▶ ACC ──TSTORE──▶ GM
                    │
                    └──────▶ VEC (Vector 运算)

    1.1 Rationale¶

    For the Level-2/Level-3 profiles documented here, PTO IR models tiles as buffers rather than SSA values. A pto.tile_buf denotes a storage object with an explicit lifetime, not a pure value.

    为什么用 Buffer 而非 SSA？¶

    核心问题：内存分配和流水线调度都是 NP-hard 问题，在一个 Pass 中同时处理两者是不可行的。

    设计决策：

    方面 Level-1 (SSA) Level-⅔ (Buffer)
    语义 纯值，无副作用 存储对象，有生命周期
    内存复用 编译器自动 用户/框架显式管理
    调度控制 编译器自动 用户可精细控制
    适用场景 高层优化 低层流水线编排

    示例：显式 Buffer 生命周期¶

    // 分配两个 tile buffer
%a0 = pto.alloc_tile : !pto.tile_buf<loc=vec, dtype=f16, rows=16, cols=16,
                                      v_row=16, v_col=16, blayout=row_major,
                                      slayout=none_box, fractal=512, pad=0>
%a1 = pto.alloc_tile : !pto.tile_buf<loc=vec, dtype=f16, rows=16, cols=16,
                                      v_row=16, v_col=16, blayout=row_major,
                                      slayout=none_box, fractal=512, pad=0>

// 从全局内存加载到 buffer
pto.tload ins(%pv0 : !pto.partition_tensor_view<16x16xf16>)
          outs(%a0 : !pto.tile_buf<...>)
pto.tload ins(%pv1 : !pto.partition_tensor_view<16x16xf16>)
          outs(%a1 : !pto.tile_buf<...>)

    在这个模型中：

    • 用户/高层框架通过 pto.alloc_tile 显式管理 buffer 复用
    • PTO-AS 的 Pass 专注于调度和流水线编排
    • 生命周期不重叠的 buffer 可以复用同一块物理内存
